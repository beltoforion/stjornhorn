Stjörnhorn v0.3.0

A node-based image- and video-processing playground for the desktop.

Overview

Stjörnhorn is a desktop application for building image- and video-processing workflows in a node-based visual editor. Drop sources, filters, and sinks onto a canvas, wire them up, press Run, and watch the output update in the built-in viewer.

Typical uses:

  • Experiment with image-processing operations (dithering, thresholding, normalisation, scaling, channel splitting, …) without writing code.
  • Compose filters into reusable flows and save them to disk.
  • Batch-convert and composite images by wiring up file sources and sinks.
  • Drive parameters from numeric streams to animate values across a video — slide an overlay, ramp a threshold, fade in a mask.

Installation

Prerequisite: Python 3.10 or newer.

pip install -r requirements.txt

Or install in editable mode together with the stjornhorn console entry point: 

pip install -e .

Pre-built binaries (Windows zip, Linux AppImage) are also attached to each tagged GitHub release — no Python toolchain required for end users.

Running

python src/main.py

Optional command-line arguments:

FlagDescription
--no-splash Skip the startup splash screen.
--flow FILE Load a flow at startup and open it directly in the editor. Accepts a full path to a .flowjs file or a bare flow name (looked up in flow/, with or without the .flowjs extension).

Unrecognised flags are forwarded to Qt — useful for -style, -platform, etc.

Start page

The start page is the landing screen when the app opens. From here you create a new flow or pick up where you left off with an existing one.

  • Name input — type a name for a new flow. Names may contain ASCII letters, digits, and the characters _ # + -. The input also sets the filename stem that Save will use later (e.g. the name dither_lab saves to flow/dither_lab.flowjs).
  • Create — opens the node editor with a fresh empty flow whose name matches the input. Disabled until the input contains a valid name; pressing Enter in the input triggers it.
  • Open (toolbar, top) — launches a file dialog to load any .flowjs file from disk. The dialog starts in the app's flow/ directory but you can browse anywhere.
  • Recent Flows — a grid of tiles for flows you have recently created, opened, or saved. Click a tile to open that flow. Each tile shows the flow's name; hover to see the full path. The grid reads "No recent flows" until you have used one.

Node editor

The node editor is where flows are built and run. A flow is a graph of nodes — sources produce images, filters transform them, sinks consume them — connected by typed ports. The editor gives you a palette, a canvas to wire nodes together, an output preview, and a toolbar to drive the flow.

Layout

  • Node List (dockable, left) — the palette of every registered node, grouped into a tree by section (Sources, Sinks, Output, Color Spaces, Transform, Processing, Temporal, Math, Composit, Debug, …). Each section is collapsible; the dock has expand-all / collapse-all buttons. A search box at the top filters live and auto-expands matching groups so leaves never hide behind a closed section. Drag an entry onto the canvas to instantiate it. Toggle the dock via the View menu; it can be floated, re-docked, or closed.
  • Canvas (centre) — the flow graph. Each node shows its title, output sockets stacked at the top, input sockets with inline parameter widgets at the bottom (Blender shader-editor layout). A small × in the top-right of a node deletes it; a diagonal grip in the bottom-right resizes the node — drag wider and every inline widget grows along with the body. Scroll to zoom; middle-mouse-drag to pan. Dropping a node from the palette places it at the cursor.
  • Status bar (bottom) — shows the last successful / informational message, such as "Ran at 14:23:55" or "Saved to flow/x.flowjs". Errors pop up in a floating red banner at the top right instead, so long multi-line messages stay readable.

Connecting nodes

  • Drag from an output port (top of a node) to an input port (bottom of another). The connection is only accepted if the port types are compatible — e.g. an IMAGE_GREY output may feed an input that accepts greyscale.
  • Drag an existing link off either end to remove it.
  • One output can drive many inputs; each input accepts exactly one upstream.
  • Unconnected port circles are filled black; once connected, the dot fills with the type colour.

Toolbar — Flow section

  • Run — execute the flow once. Sources push data through the graph to the sinks. The status bar updates with the run time; any exception shows up in the error banner.
  • Save — write the current flow to flow/<name>.flowjs, where <name> is the flow's current name.
  • Save As… — write the current flow to a path you choose. The stem of the chosen filename becomes the flow's new name (which is then used by future Save clicks).
  • Open — load another .flowjs file, replacing the current flow.
  • Clear — remove every node and connection from the canvas. Asks for confirmation.

Toolbar — View section

  • Fit — zoom and scroll so the whole graph fits the viewport.
  • 1:1 — reset the view transform to 100% zoom.
  • V-Stack — align two or more selected nodes on a shared X axis and stack them top-to-bottom (preserves their current vertical order). Disabled until ≥ 2 nodes are selected.
  • H-Stack — align two or more selected nodes on a shared Y axis and arrange them left-to-right (preserves their current horizontal order). Disabled until ≥ 2 nodes are selected.
Re-runs are explicit. Editing a parameter no longer auto-triggers a run — every re-run goes through the Run button. The previous 300 ms debounced auto-run was removed in v0.1.42 to avoid spurious decode work on video flows.

Building a flow

  1. From the start page, type a name for the flow and press Create.
  2. Drag a source from the palette (e.g. Image Source) onto the canvas. Click the path widget on the node body to pick an input file.
  3. Drag one or more filters onto the canvas and wire the source's output to the filter's input.
  4. Drag a Display node onto the canvas and wire it after the last filter — its inline preview is the result, no sink required.
  5. Press Run. The status bar shows the run time; the Display node renders the live frame inside its body.
  6. Tweak parameters and press Run again. To persist work, press Save — the flow is written to flow/<name>.flowjs.

Adding an output sink

To save the result to disk, add a File Sink (single image) or Video Sink (encode a stream) downstream of your filters in addition to (or instead of) Display. The eye button next to a File Sink's path opens the written file in the OS image viewer.

Flow files

Flows are JSON files with the .flowjs extension (just JSON — the extension makes them easy to associate with the app on the desktop). The format finalised in v0.1.35; on disk every node carries a port_defaults map of the literal default for each editable port. Older flows written with the legacy params key still load — the loader reads it as a fallback.

Saved flows store paths under the app's input/ and output/ folders as relative paths, so a flow stays portable across machines that share the same input layout.

Execution model

Stjörnhorn uses a push-based dispatcher. There is no central scheduler walking the graph — each port forwards data to the next as soon as it has it.

  • A source's start() calls process_impl(), which pushes IoData onto its output ports.
  • Each OutputPort.send() forwards the payload to every connected input port.
  • An input port notifies its owner node via an internal _signal_input_ready() hook.
  • Once every waited-on input has data, the node's process() fires and the inputs are cleared so the node is ready for the next frame.
  • Stream lifetime is a separate signal: OutputPort.finish() marks an output as done and propagates downstream, so sinks know when to flush and close.

Flow runs execute on a Qt worker thread (FlowRunner) so the UI stays responsive. The currently-executing node is surfaced live in the editor via a queued signal, so you can see processing march through the graph.

Node anatomy

Every node is an instance of a Python class derived from NodeBase, SourceNodeBase or SinkNodeBase. A node has three observable surfaces:

  • Output ports — typed sockets the node emits values on. An output may fan out to many downstream inputs; an output's emits set declares which IoDataTypes it produces.
  • Input ports — typed sockets the node consumes values from. An input has at most one upstream connection (no fan-in); its accepted_types set declares which IoDataTypes it can receive. A connection is allowed only when the output's emits and the input's accepted_types intersect.
  • Parameters — editable knobs (numeric, boolean, enum, string, path, …) that configure how the node processes each frame. Parameters come in two flavours (see below); both render as inline widgets on the node body.

Output ports

Declared in the node's constructor with OutputPort(name, emits), e.g. OutputPort("image", {IoDataType.IMAGE}). A node with several outputs (RGBA Split, HSV Split, FFT 2D, Sliding Window) sends to each one independently per dispatch. Each send() auto-stamps a per-port frame_index counter and the current values of the node's SCALAR input ports onto the outgoing IoMeta — see Frame metadata.

Input ports

Declared with InputPort(name, accepted_types, …). Two important flags shape an input's behaviour:

  • optional=True — the dispatcher does not wait for this input. If unconnected, the node fires once every required input has data; if connected, the optional input is treated as required (so a producer that emits matching-frame data isn't raced). Used for, e.g., the alpha plane on RGBA Join.
  • hold_last=True — the input retains its last received value across clear() and across the upstream's finish(). Used to pair a one-shot source (an image, a CSV) with a streaming clock — the held input stays alive while the clock keeps ticking. See Held inputs.

Held ports render with a dashed coloured ring around the socket dot in the editor.

Parameters

Parameters are declared at class level as descriptor objects from core.params. Every descriptor type maps to an IoDataType and a default widget:

Descriptor Backs port type Widget Notes
IntParam SCALAR Integer spin box Optional min / max raise on out-of-range writes.
OddIntParam SCALAR Odd-only integer spin box Steps in twos and rounds even values up. For OpenCV-style kernel sizes.
FloatParam SCALAR Float spin box Optional min / max, with min_exclusive / max_exclusive for strict bounds. Carries step / decimals hints.
ClampedFloatParam SCALAR Float spin box Out-of-range writes are silently clamped instead of raising. For sliders where overshoot is just saturation.
BoolParam BOOL Checkbox Coerces with bool(value).
EnumParam ENUM Combo box Takes an IntEnum class; member name, value, or instance all coerce to the right member.
StringParam STRING Line edit Optional placeholder and max_length.
FilePathParam PATH Path widget (line edit + browse + open) mode = "open" / "save" / "directory"; filter for the file dialog; base_dir stashes paths inside the app folder as relative.

Port-style vs. constant parameters

Each parameter is one of two flavours, controlled by the descriptor's constant= flag:

  • Port-style (default, constant=False) — the framework auto-creates an InputPort for the parameter. The widget sits on the input row alongside a socket dot, and any compatible upstream value can drive the parameter per-frame. The framework writes the upstream value into self._<name> on every process() call, so node code reads its parameters uniformly with no "is this connected?" branch (see Param-as-port).
  • Constant (constant=True) — the parameter is registered on node.params instead of becoming an input port. The widget renders between the output and input rows with an italic caption and no socket dot. Used for config that's set once by the user (file paths on sources, codecs on sinks, layout strings on Mosaic / JoinDatasets).

Lifecycle hooks

A node sees a small set of hooks during a flow run; subclasses override these rather than the @final public wrappers:

HookWhen
_before_run_impl() Once before each run. Reset per-run state (frame buffers, video writers, …).
process_impl() Once per dispatch when every required input has data. Read inputs, compute, send to outputs.
iter_frames() Source-only. Yields once per emitted frame. Default: one-shot. Streaming sources override to a true generator.
_on_finish() Once every clock input has finished. Default forwards finish() to all outputs; sinks override to flush.
_on_skipped_changed(b) Whenever the node's mute state flips. Default: no-op.
_after_run_impl(success) Once after each run. Tear down per-run state.
on_flow_loaded() After deserialisation, before any UI repaint. Cache-warm work that would otherwise stall first paint.

Sources additionally override the read-only is_reactive property — True for one-shot sources (image, CSV, constant value) so the editor re-runs on any parameter edit; False for streaming sources (video, directory, range) so the run only starts on Run.

Source / Filter / Sink

  • Source (SourceNodeBase) — outputs only, no inputs. Drives the flow.
  • Filter (NodeBase) — both inputs and outputs. Transforms data.
  • Sink (SinkNodeBase) — inputs only, no outputs. Side-effects (writing to disk, encoding video). Sinks override _on_finish() so the lifecycle signal terminates rather than propagating further.

Data types

Every value flowing across a port is wrapped in an IoData envelope discriminated by an IoDataType:

TypePayloadUsed for
IMAGE 3-D uint8 array (H × W × 3, BGR) Colour frames.
IMAGE_GREY 2-D uint8 array (H × W) Single-channel images, masks, binary output.
SCALAR 0-d numpy array Numeric streams that drive parameters (counters, ramps).
MATRIX 2-D numpy array, arbitrary dtype Transformations, kernels, intermediate stats, FFT spectra.
DATASET pandas.DataFrame Labeled tabular data — seismic traces, CV curves, I-V sweeps, spectra. df.attrs carries free-form metadata (sample rate, units, station, …).
BOOL Python bool Switches and toggles on params.
STRING Python str Text-valued params.
ENUM IntEnum member or int Selectors (interpolation, codec, dither method).
PATH pathlib.Path File / folder params.

IMAGE and IMAGE_GREY together make up the image-typed set: filters that work on either (e.g. Median, Scale, Shift) declare their input as accepting both, and pass-through helpers preserve the type with IoData.with_image().

Frame metadata (IoMeta)

Every IoData envelope carries an IoMeta bag — an open-ended str → Any mapping that travels with the payload. It has no fixed schema; any node can stamp any key. The framework follows a few conventions so different nodes recognise each other's stamps. Reserved names — frame_index, source_path, timestamp — are framework-owned, and a port declared with one of those names is rejected at construction.

Framework-stamped keys

Every output port stamps these on every emit, with no node code involved.

KeyStamped byValue
frame_index Every OutputPort.send() Per-port emit counter, starting at 0 each run.
<scalar_port_name> Every OutputPort.send() Current value of every SCALAR input port on the emitting node, stamped under the port's name. Falls back to the port's default_value when no upstream is connected. Lets a downstream filename template reference $tick$ against whatever the node read this frame.

Conventional keys stamped by individual nodes

KeyStamped byValue
source_path Image Source, CSV Source, Directory Source Absolute pathlib.Path the frame was loaded from. Filename templates resolve $source_stem$ / $source_name$ / $source_ext$ against this.
tick Repeat Auto-stamped via the SCALAR-port rule above (Repeat's tick input is SCALAR). Read by $tick$ in File Sink templates.
window_start / window_end Sliding Window Sample-row indices of the current window, stamped on both output payloads each tick. Plot Series reads these to draw a moving band overlay.
timestamp Reserved for the run start time (planned). —

DATASET-side metadata

For DATASET payloads, a parallel channel exists on the DataFrame itself: df.attrs. Convention:

AttrStamped / read byMeaning
source_path CSV Source (write); plotters (read) Path the dataset was loaded from.
units Directional Projection, plotters {column_name: unit_string} mapping consumed by axis labels.
sample_rate Forwarded by all DATASET filters; read by Add Index Column and Spectrum docs as a hint. Sample rate in Hz.
thetas_rad Directional Projection (write); Polar Heatmap (read) Per-column azimuth angles in radians, so polar visualisers can bind columns to angles without parsing column names.

Custom nodes are free to add domain-specific keys to IoMeta or df.attrs; downstream consumers decide whether to read them. To preserve metadata through a pass-through filter, prefer in_data.clone(payload=new_array) over IoData.from_*(...) — the former carries meta forward, the latter starts fresh.

Param-as-port

Every editable property on a node is a socket (Blender-style). Numeric, boolean, enum, and path params have inline widgets right next to their socket dots. Wire any compatible value source into a param port and the streamed value drives that param per frame; leave it unconnected and the inline widget acts as the literal value.

On every process() call, the framework writes any connected input port's current value into the matching self._<port_name> attribute and restores the user-set value afterwards. As a result, a node's process_impl() can read its parameters uniformly with no per-port "is this connected?" branch.

When a port is driven, the inline widget for that param is greyed out — the upstream wins until you disconnect it.

Held inputs

Inputs declared with hold_last=True retain their last received value across both clear() and upstream finish(). Held inputs also do not count as lifecycle drivers — only non-held (clock) inputs propagate finish through the graph.

The pattern is "one-shot reference data alongside a streaming clock". Repeat uses it for its data input (any payload kind) so a single image or CSV survives across many ticks of its tick clock; Sliding Window uses it on its dataset input so a one-shot CSV walks alongside a streaming window_index counter.

Held ports render with a dashed coloured ring around their socket dot in the editor.

Skipping nodes

Nodes have a Blender-style mute mode: a skipped node forwards each output from the first type-compatible input, bypassing its own logic. Useful for A/B-comparing a flow with and without a filter without rewiring.

A node is is_skippable if at least one of its inputs has a type-compatible match among its outputs. Sources (no inputs) and sinks (no outputs) are never skippable. Param-style ports are naturally invisible to skip detection, so adding more of them never breaks a node's skippability.

Sources

Sources have outputs only — they produce data and drive the graph. Reactive sources emit a single value, so the editor latches their output across runs (handy for still images that stay constant while a video stream pumps frames).

Image Source

Reads a single still image (JPEG, PNG, WebP, CR2 RAW) from disk. Reactive — the flow re-runs on any parameter edit. Stamps source_path onto outgoing IoMeta.

Out: image (IMAGE) · Param: file_path

Video Source

Decodes frames from a video file (MP4, AVI, MOV, MKV) and streams them. Not reactive. max_num_frames = -1 decodes the whole stream; positive caps the count.

Out: image (IMAGE) · Params: file_path, max_num_frames

Directory Source

Streams every image in a folder as frames, sorted lexicographically. Stamps source_path per frame so file-name templating downstream tracks the originating file.

Out: image (IMAGE) · Params: directory, include_subdirectories

CSV Source

Reads a CSV file into a DATASET (a pandas.DataFrame). Lines beginning with # are skipped, so files with a metadata header (seismic ASCII traces, gnuplot output) load without extra setup. Stamps source_path both on IoMeta and on df.attrs. Reactive.

Out: dataset (DATASET) · Params: file_path, has_header, delimiter, …

Gradient Source

Procedurally generates a single-channel gradient image (vertical, horizontal, or radial; symmetric or linear). Useful as a procedural mask for Masked Blend (tilt-shift, vignette, cross-fade) without having to ship a hand-painted PNG. Reactive.

Out: image (IMAGE_GREY) · Params: width, height, direction, mode, band_width

Range Source

Numeric range source emitting one SCALAR per frame. Wire into a Display to watch the value live, or into a param port to ramp it across a stream. Whole-number increments emit ints; fractional emit floats. Streaming (not reactive).

Out: value (SCALAR) · Params: min_value, max_value, increment

Constant Value

Reactive source that emits a single SCALAR, latched on streaming consumers. Use as a fixed factor or offset feeding into Math without spinning up a second Range Source.

Out: value (SCALAR) · Param: value

Output

Display

Pass-through node that surfaces each frame in an inline preview rendered inside the node body. Drop it anywhere in a flow to watch frames flow through. Resize the node to grow the preview. Accepts IMAGE, IMAGE_GREY, SCALAR and MATRIX payloads — SCALAR / MATRIX render as text and the inline preview is the result, no sink required. Image previews show an exponentially-smoothed FPS read-out in the corner.

In: image (IMAGE / IMAGE_GREY / SCALAR / MATRIX) · Out: image (passthrough)

Sinks

Sinks have inputs only — they consume data as a side effect (writing to a file, encoding a video) and don't propagate further. Sinks are optional: a flow that ends at a Display node runs without one.

File Sink

Writes each incoming frame to disk. output_path is a filename template — $frame_index$, $source_stem$, $source_name$, $source_ext$, $flow_name$, plus any SCALAR-port value an upstream filter stamped (e.g. $tick$ from Repeat). Width syntax $tok:N$ zero-pads; with no placeholders the file is overwritten on every frame.

In: image (IMAGE / IMAGE_GREY) · Param: output_path

Video Sink

Encodes incoming frames to a video file via cv2.VideoWriter. The writer opens lazily on the first frame (dimensions inferred from the data), frames are written as they arrive, and the container is finalised when the runner signals end-of-stream. Greyscale inputs are promoted to BGR automatically. output_path is a filename template resolved from the first frame's meta.

In: image (IMAGE / IMAGE_GREY) · Params: output_path, fps, codec

Color Spaces

Grayscale

Converts a BGR colour image to a single-channel greyscale image (cv2.cvtColor(..., COLOR_BGR2GRAY)).

In: image (IMAGE) · Out: image (IMAGE_GREY)

RGBA Split

Splits a BGR / BGRA image into four single-channel outputs (B, G, R, A). Plain BGR inputs emit a constant-255 alpha plane so downstream nodes always see a well-defined alpha.

In: image (IMAGE) · Outs: B, G, R, A (IMAGE_GREY each)

RGBA Join

Merges single-channel inputs back into a single multi-channel image. The alpha input is optional — connect it for a BGRA output, leave it open for BGR. Inverse of RGBA Split.

Ins: B, G, R, A (IMAGE_GREY; A optional) · Out: image (IMAGE)

HSV Split

Splits a BGR / BGRA image into its HSV components. Hue uses the full 0..255 range so HSV Join round-trips back exactly. BGRA inputs drop the alpha channel (HSV has none).

In: image (IMAGE) · Outs: H, S, V (IMAGE_GREY each)

HSV Join

Merges three single-channel inputs (H, S, V) back into a BGR image. Pixel-exact inverse of HSV Split.

Ins: H, S, V (IMAGE_GREY) · Out: image (IMAGE)

HSL Split

Splits a BGR / BGRA image into its HSL components. Same conventions as HSV Split.

In: image (IMAGE) · Outs: H, S, L (IMAGE_GREY each)

HSL Join

Merges three single-channel inputs (H, S, L) back into a BGR image. Pixel-exact inverse of HSL Split.

Ins: H, S, L (IMAGE_GREY) · Out: image (IMAGE)

Transform

Scale

Resizes by a percentage factor (scale_percent, 100 = no change). Interpolation is selectable: Nearest, Linear, Cubic, Area, Lanczos4.

In/Out: image (IMAGE / IMAGE_GREY) · Params: scale_percent, interpolation

Resize

Resize to an explicit (width, height) using one of three layout strategies: SCALE (stretch, ignore aspect), CROP_OR_FILL (centre-crop / black-fill at native scale), or BEST_FIT (letterbox / pillarbox). Black is used for fills; on BGRA that means transparent black.

In/Out: image (IMAGE / IMAGE_GREY) · Params: width, height, method

Shift

Translates by integer pixel offsets. Output keeps the original canvas size; pixels that move off-frame are dropped, newly exposed areas are black.

In/Out: image (IMAGE / IMAGE_GREY) · Params: offset_x, offset_y

Crop

Cuts a rectangular ROI (x, y, width, height) out of the input. The ROI is clamped to the input bounds, so the node always emits a positive-area image even when the rectangle extends beyond the input.

In/Out: image (IMAGE / IMAGE_GREY) · Params: x, y, width, height

Rotate

Rotates by an arbitrary angle (degrees, CCW) around the image centre. With expand=True the output canvas grows so no pixel is clipped; with expand=False the input dimensions are preserved.

In/Out: image (IMAGE / IMAGE_GREY) · Params: angle, expand

Flip

Mirrors the image horizontally, vertically, or both (the latter being equivalent to a 180° rotation).

In/Out: image (IMAGE / IMAGE_GREY) · Param: mode

Processing

Adaptive Gaussian Threshold

Adaptive binary thresholding using a Gaussian-weighted local mean (cv2.adaptiveThreshold). Colour inputs are reduced to greyscale first; the output is always a single-channel binary image.

In: image (IMAGE / IMAGE_GREY) · Out: image (IMAGE_GREY) · Params: block_size, c

Dither

Reduces the image to two levels using a selectable algorithm: Bayer 2/4/8, random noise, Floyd–Steinberg, Stucki, Atkinson, Burkes, Sierra, Diffusion-X, or Diffusion-XY. Error-diffusion kernels are JIT-compiled via numba for interactive speed. Colour inputs are auto-converted to grey; output is always greyscale.

In: image (IMAGE / IMAGE_GREY) · Out: image (IMAGE_GREY) · Param: method

Median

Square-kernel median blur (cv2.medianBlur). Works on colour or greyscale; output type matches input.

In/Out: image (IMAGE / IMAGE_GREY) · Param: size

Gaussian Blur

Configurable Gaussian smoothing (cv2.GaussianBlur). Independent kernel radius and sigma (sigma=0 derives from the kernel size). Works on colour or greyscale.

In/Out: image (IMAGE / IMAGE_GREY) · Params: ksize, sigma

Normalize

Histogram equalisation (cv2.equalizeHist). Colour inputs are equalised per channel; greyscale inputs are equalised directly. Output type matches input.

In/Out: image (IMAGE / IMAGE_GREY)

Invert

Per-channel image inversion (255 - pixel). Works on colour or greyscale; type-preserving.

In/Out: image (IMAGE / IMAGE_GREY)

Apply Colormap

Colorize a greyscale image with a chosen colormap and emit a 3-channel BGR image. Palettes include the perceptually-uniform family (Viridis, Plasma, Magma, Inferno), classic FFT / spectrogram palettes (Jet, Turbo) and utility palettes (Hot, Bone, Parula, Ocean, Cool). Expects 0..255 input — apply log compression upstream for HDR sources.

In: image (IMAGE_GREY) · Out: image (IMAGE) · Param: colormap

NCC

Normalised cross-correlation template matching (cv2.matchTemplate with TM_CCORR_NORMED). Searches for a file-loaded greyscale template inside the input and emits a uint8 response map. retain_size=True (default) pads the score map back to the input size and centres each response on its corresponding template-centre pixel.

In: image (IMAGE_GREY) · Out: image (IMAGE_GREY) · Params: template, retain_size

Temporal

Temporal nodes operate across consecutive frames of a video stream. They hold internal state across frames and reset at the start of each run.

Frame Difference

Per-pixel absolute difference between the current frame and the previous one. The first frame produces a black output; shape changes mid-stream reset the buffer rather than raising.

In/Out: image (IMAGE / IMAGE_GREY)

Temporal Mean

Rolling per-pixel arithmetic mean over the last window frames. Reduces additive Gaussian-style noise on a static scene; smears motion. While the buffer fills, the mean of however many frames have arrived so far is emitted.

In/Out: image (IMAGE / IMAGE_GREY) · Param: window

Temporal Median

Rolling per-pixel median over the last window frames. Strong against transient outliers (single-frame spikes, flicker, salt-and-pepper noise) without the smearing a mean would produce.

In/Out: image (IMAGE / IMAGE_GREY) · Param: window

Frequency

Frequency-domain operations on greyscale images and DATASETs.

FFT 2D

Computes the 2-D discrete Fourier transform of a greyscale image. Emits the fftshifted complex spectrum on spectrum (MATRIX) and a log-scaled normalised magnitude image on magnitude (IMAGE_GREY) for direct preview. Pairs with Inverse FFT 2D for a pixel-exact round trip.

In: image (IMAGE_GREY) · Outs: spectrum (MATRIX), magnitude (IMAGE_GREY)

Inverse FFT 2D

Inverse of FFT 2D. Expects the fftshifted complex spectrum on spectrum and emits a uint8 greyscale image.

In: spectrum (MATRIX) · Out: image (IMAGE_GREY)

Spectrum

Per-column magnitude FFT of a DATASET. The output's row index is frequency in Hz (index.name = "frequency_hz") and the column names match the input — N channels in produces N channels out, ready for Plot Series or Polar Heatmap. Hann window suppresses spectral leakage on short windows; db_scale converts to dB.

In/Out: dataset (DATASET) · Params: sample_rate, freq_max, window, db_scale

Math

The math nodes operate on SCALAR streams. Combine them with Range Source / Constant Value to drive any numeric param on any node from a computed value.

Math

Evaluates a small expression DSL over a pool of nine optional SCALAR inputs v_1 … v_9. The grammar permits arithmetic, the min / max / abs family, and a curated subset of math.*; attribute access, subscripts, lambdas and other sandbox-escape primitives are rejected at compile time. Only the connected slots render in the editor (uses SHOW_ONLY_USED_INPUTS).

Ins: v_1 … v_9 (SCALAR; optional) · Out: value (SCALAR) · Param: expression

Clamp

Clamps a scalar input to [min_value, max_value]. If the bounds are inverted they're swapped before clamping, so a transient inversion during editing is tolerated.

In/Out: value (SCALAR) · Params: min_value, max_value

Composit

Mosaic

Variable-layout image composer. The layout is a small descriptor string: rows separated by ;, cells inside a row by ,, each cell the 1-based index of an image_i input (e.g. 1,2;3). Within a row, images scale aspect-preserving to the row's max height; rows then scale to the widest row's width. No black bars, no forced grid. Carries a fixed pool of nine optional inputs; only those needed by the layout render in the editor.

Ins: image_1 … image_9 (IMAGE / IMAGE_GREY; optional) · Out: image (IMAGE / IMAGE_GREY) · Param: layout

Overlay

Composites an overlay image onto a base. The overlay is optionally rotated and scaled, then blended so its centre lands at (xpos, ypos) with opacity alpha. Every numeric param (scale, angle, xpos, ypos, alpha) is drivable through its socket — wire ramps in for sliding, zooming, fading or rotating animations. BGRA overlays use their alpha channel as a per-pixel mask, with alpha as a global multiplier on top.

Ins: base, overlay (IMAGE / IMAGE_GREY) · Out: image · Params: scale, angle, xpos, ypos, alpha

Masked Blend

Per-pixel cross-fade of two images driven by a greyscale mask: out = base*(1-m) + overlay*m with m = mask/255. Unlike Overlay, the mask is a separate input so any greyscale producer (a Gradient Source, an FFT magnitude, a threshold) can drive it. Mismatched shapes are reconciled: mixed colour / greyscale inputs promote to colour, mask is resized to match base.

Ins: base, overlay, mask (IMAGE / IMAGE_GREY) · Out: image

Data

Data nodes operate on DATASET payloads — pandas.DataFrame objects with labeled columns and free-form metadata in df.attrs.

Add Index Column

Prepend a synthetic numeric column to the input DATASET. Useful when a downstream renderer needs an explicit X axis but the dataset has no natural one (e.g. a one-column trace from CSV Source). Set step = 1 / sample_rate for a seconds axis.

In/Out: dataset (DATASET) · Params: name, start, step

Join Datasets

Merges two or more DATASET inputs into one. Carries a fixed pool of nine optional dataset_i ports — only the connected ones render in the editor. Optional column_names renames the first column of each input before joining (handy when several single-column sources all carry the generic name c0). df.attrs from the first connected input is forwarded.

Ins: dataset_1 … dataset_9 (DATASET; optional) · Out: dataset (DATASET) · Param: column_names

Directional Projection

Projects a 2-component vector signal onto n_angles directions. For each azimuth θ_j = j · 2π / n_angles emits a column r_j(t) = x·cos θ_j + y·sin θ_j. Output columns are named "<deg>°"; the exact angles in radians are stamped on df.attrs["thetas_rad"] for machine consumers (e.g. Polar Heatmap).

In/Out: dataset (DATASET) · Params: x_column, y_column, n_angles

Sliding Window

Slices a DATASET into a sliding window driven by a SCALAR clock. Each tick re-emits two DATASETs — a slice (dataset_windowed) and the unmodified original (dataset_full) — both stamped with window_start / window_end on IoMeta. The dataset input is held (hold_last=True) so a one-shot CSV survives across the streaming clock's many ticks.

Ins: dataset (DATASET, held), window_index (SCALAR) · Outs: dataset_windowed, dataset_full · Params: window_size, step

Visualization

Visualization nodes render DATASETs to images, suitable for chaining into Display, a Mosaic, or a File Sink.

Plot XY

Renders two columns of a DATASET as an XY line plot, via matplotlib's off-screen Agg backend. Axis labels come from the column names; df.attrs["units"] adds unit suffixes when present.

In: dataset (DATASET) · Out: image (IMAGE) · Params: x_column, y_column, width, height, …

Plot Series

Synthesises a time axis and renders every column of the input DATASET as an independent time-series trace, stacked vertically with a shared time axis. Set step = 1 / sample_rate for a seconds axis. Reads window_start / window_end from IoMeta (typically stamped by Sliding Window) to overlay a moving band spanning every panel.

In: dataset (DATASET) · Out: image (IMAGE) · Params: step, y_columns, width, height, …

Hodogram

Plots two SCALAR-stream DATASETs (two-channel position / particle-motion / displacement traces) as a time-coloured 2-D trajectory with an optional fitted principal axis overlay. Useful for polarisation analysis on seismic / geophone data.

Ins: x, y (DATASET) · Out: image (IMAGE) · Params: width, height, principal_axis, …

Polar Heatmap

Renders a polar heatmap of an N-direction DATASET (typically the output of Directional Projection or Spectrum). Reads angles from df.attrs["thetas_rad"] when present; otherwise parses degrees from column names.

In: dataset (DATASET) · Out: image (IMAGE) · Params: width, height, colormap, …

Streaming

Repeat

Re-emits a held payload once per clock tick. Pairs a one-shot upstream (an image, a CSV) with a streaming SCALAR clock so the held payload fires once per tick. Each emission carries meta["tick"] = <clock value> automatically (via the SCALAR-port auto-stamp), so a downstream File Sink template can reference $tick$ without a tick port of its own. The data input is held (hold_last=True); the tick input drives the lifecycle.

Ins: data (any, held), tick (SCALAR) · Out: data (any)

UI

Pass-through nodes that surface a UI side-effect alongside the frame.

Delay

Sleeps for a configurable number of seconds before forwarding each frame. Useful as a "slideshow" knob, or to make per-frame status updates visible during development.

In/Out: image (IMAGE / IMAGE_GREY) · Param: delay_seconds

Notify

Surfaces a status message in the floating banner. severity chooses INFO (blue) / WARNING (amber) — run continues — or ERROR (red), which raises a RuntimeError and aborts the run. The message is a port-style input: type a literal or wire any STRING source in to drive it per frame.

In/Out: image (IMAGE / IMAGE_GREY) · Params: message, severity

Experimental

Effects-style nodes that are not part of the production pipeline but are interesting on their own.

Subpixel Mosaic

Renders a BGR image as a stylised RGB sub-pixel mosaic, scattering each source pixel across three mono-channel sub-pixels echoing the R/G/B arrangement of a physical display's shadow mask. keep_aspect rescales to the original aspect ratio; output_grayscale drops the colour and emits the per-pixel sample intensity.

In: image (IMAGE) · Out: image (IMAGE / IMAGE_GREY) · Params: keep_aspect, output_grayscale

Debug

Debug nodes are utilities for testing the framework itself — confirming param wiring, simulating slow nodes, exercising the error banner. They live in the palette under their own section so they're out of the way for normal use.

Debug Params

Exhaustive node exposing one parameter of every known NodeParamType. Image is passed through unchanged. Exists so every widget kind can be rendered, edited, saved and loaded through a single node.

In/Out: image (IMAGE / IMAGE_GREY) · Params: file_path, count, factor, label, enabled, mode

Throw Exception

Raises on every process_impl call. Use to confirm the error banner pops up and that flows recover cleanly when a node blows up mid-graph.

In/Out: image (IMAGE)

Meta Inspector

Pass-through node that surfaces each frame's IoMeta to a preview widget. Accepts every payload kind so it can sit inline anywhere as a debug probe; the inline preview prints the field-by-field text on the main thread.

In/Out: data (any IoDataType)

Play Gate

Buffers frames until the user clicks the inline Play button. Each click releases one frame downstream — the oldest in the queue, so the user steps through the stream in arrival order. The queue is unbounded; honest about memory cost rather than silently dropping. Drains its buffer when toggled into skip mode.

In/Out: data (any IoDataType)

File locations

In dev mode (running python src/main.py from a clone), all files live next to the source tree. In a frozen bundle they split: read-only data sits inside the bundle (sys._MEIPASS), writable data moves to a per-user directory.

Purpose Dev mode Frozen (Linux) Frozen (Windows)
Saved flows flow/ ~/.local/share/Stjornhorn/flow/ %LOCALAPPDATA%\Stjornhorn\flow\
Sample inputs input/ ~/.local/share/Stjornhorn/input/ %LOCALAPPDATA%\Stjornhorn\input\
Default output dir output/ ~/.local/share/Stjornhorn/output/ %LOCALAPPDATA%\Stjornhorn\output\
Logs logs/image-inquest.log ~/.local/share/Stjornhorn/logs/… %LOCALAPPDATA%\Stjornhorn\logs\…
User-defined nodes ~/.image-inquest/user_nodes/

On first launch of a frozen bundle, the per-user directories are created and seeded from the bundled samples — only files that don't already exist are copied, so anything you save persists across launches.

User-defined nodes

Drop a Python module under ~/.image-inquest/user_nodes/ that defines a subclass of NodeBase, SourceNodeBase, or SinkNodeBase and Stjörnhorn picks it up at startup via the same AST-based registry scan it uses for built-in nodes. Declare your inputs as InputPort objects (with type, default, and widget metadata) and your outputs as OutputPort objects, implement process_impl(), and your node appears in the palette under whichever section=… string you passed to super().__init__.
