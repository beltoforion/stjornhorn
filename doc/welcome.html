Welcome to Stjörnhorn v0.3.0

A node-based image- and video-processing playground.

Getting started

  1. Create a flow — type a name and press Create, or open an existing .flowjs.
  2. Drop nodes from the list on the left onto the canvas.
  3. Wire them up by dragging output ports to input ports.
  4. Press Run and watch any inline Display nodes update.

Node categories

Sources

Load still images (JPEG, PNG, CR2) or video files (MP4, AVI, MOV, MKV) as streams of frames.

Filters

Scale, shift, blur, threshold, dither, split/join RGBA channels, overlay with per-pixel alpha, and match templates with NCC.

Sinks

Write frames to image files or encode video (MP4V, XVID) with live preview via the Display node.

What's new in v0.3.0

  • Variable-arity inputs on Math, JoinDatasets and Mosaic. Each node carries nine optional input slots (v_1..v_9, dataset_1..dataset_9, image_1..image_9) but the editor only shows up to the last connected row plus one empty tail — a fresh node looks like a single-input node and the body grows one row at a time as you wire more upstreams. Math expressions reference inputs by name (v_1 + v_2, sin(v_1 * pi/180) * v_3); Mosaic's layout descriptor uses comma-separated cells per row and ; between rows ("1,2", "1,2;3,4", "1,2;3") — every image is scaled aspect-preserving so rows of unequal width are matched without black bars and without a fixed cell grid. Saved flows from the older letter / digit-grid eras need to be rebuilt; bundled demos already migrated.
  • Filename templating on FileSink / VideoSink. output_path is now a template — $frame_index$, $source_stem$, plus any meta key, expand at write time. Width syntax $tok:N$ zero-pads. FileSink gained a tick SCALAR input so a streaming counter can drive multiple writes (an image source plus RangeSource(1..10) → tick + out_$tick:2$.png writes ten numbered files). The path field has a hover tooltip listing every token and a live preview underneath showing how the template would render.
  • Per-frame metadata. Every IoData now carries an open-ended IoMeta bag (frame_index, source_path, timestamp, plus any custom keys). Auto-stamped at OutputPort.send; sources fill in their file paths. Foundation for filename templating and animation flows.
  • Latched inputs (hold_last). A new InputPort flag keeps the last received value alive across clear() and across the upstream's finish(), and excludes the port from lifecycle shutdown. Lets a one-shot source (an image, a CSV) sit alongside a streaming counter without going stale. Held ports render with a dashed ring in the editor.
  • Debug nodes. Two new nodes under Debug: Meta Inspector (pass-through probe that surfaces every frame's meta in its body) and Play Gate (pass-through with a Play button that releases queued frames one click at a time, FIFO order, drains automatically when skipped).
  • Range Source. Renamed from Value Source; the node always emitted a bounded range, not a single value. Bundled flows updated; saved flows referencing ValueSource need to be rebuilt.
  • App name realigned. Internal APP_NAME is now "Stjörnhorn", matching the brand. User-visible captions are unchanged.
  • Maintainer docs centralised. Architecture reference (doc/internal/dataflow.md) and refactoring backlog (doc/internal/refactoring.md) now live alongside diagrams under doc/internal/.
  • Versioning reset. Stjörnhorn now uses four-component versions Major.Minor.Release.Build. The displayed version and "What's new" headings drop the trailing build digit and group changes at the M.m.r level — every PR ticks the build digit, but a new "What's new" block only appears when M.m.r moves. The previous 0.2.x line has been retired with this slate.

Tips

  • Recent flows appear on the start page for quick access.
  • User-defined nodes live under ~/.image-inquest/user_nodes/.
  • Run with --flow NAME to jump straight into a saved flow.
  • Press F11 with the output inspector focused to toggle fullscreen preview.
